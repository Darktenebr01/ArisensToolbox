# Changelog

Every released build, newest first. The bridge version in parentheses is the
game-side script shipped with that client.

## v0.180

The app and the cheat table now ship the same bridge (v1.89.82).

- CT v1.88 embedded bridge 1.89.80 with kill v14. The app v0.179 shipped
  bridge 1.89.81 with the unlearn commands but kill v13. Two different builds
  both called themselves 1.89.80, and each front-end would have overwritten
  the other's bridge on install.
- Merged both tracks: kill v14 (DeadPoint read-backs, plus the v13 finding
  that the element Hit and the handle Hit are separate state) and core and
  weapon skill unlearning, on top of every earlier fix. The result is bridge
  1.89.82.
- The app ships 1.89.82. CT v1.90 embeds the same bridge, so opening either
  front-end no longer downgrades the other.
- CT v1.90 adds **Unlearn selected** and **Unlearn ALL (vocation)** to its
  Weapon Skills and Core & Augments tabs, using the same bridge commands as the
  app. Equipped skills are skipped and noted on each tab; the CT has no undo
  stack.
- No app UI changed in this build; it is a bridge/version alignment release.

## v0.179

Weapon skills can be unlearned, not just learned (bridge v1.89.81).

- **Unlearn selected** and **Unlearn all (vocation)** on the Weapon Skills
  screen. Both write to the save and record an undo that relearns the skills
  at their previous levels.
- The bridge removes the skill's entry from
  `SkillContext.EnabledCustomSkills`, verifies it with `isCustomSkillEnable`,
  and falls back to clearing the list and rebuilding the remaining entries
  with their levels if direct removal is not available. The route taken and
  any failed read-back are returned and logged.
- Equipped skills are never removed: a slot pointing at a forgotten skill
  would leave the loadout in a state the game menu cannot repair. The client
  and the bridge both skip them, and the status line says how many were
  skipped.
- New bridge commands: `disable_wskill`, `disable_wskills`.
- Weapon skill rows now read "learned" / "not learned" with their level;
  the learn buttons and level box use that wording too.
- Command-surface test covers the new commands; the interaction suite covers
  unlearn-one, unlearn-all, equipped-skill protection and both undos.

## v0.178

Core skills can be unlearned, not just learned (bridge v1.89.80).

- **Unlearn selected** and **Unlearn all (vocation)** on the Core Skills
  screen. Both write to the save and record an undo that relearns the skills.
- The bridge removes ids from `SkillContext.EnableNormalSkills` (the list the
  community "Reset normal skill" mod clears), verifies every id with
  `isNormalSkillEnable`, and falls back to clearing the list and re-adding the
  skills that should stay if direct removal is not available on the build.
  The route taken and any id that failed the read-back are returned and logged.
- New bridge commands: `disable_nskill`, `disable_nskills`.
- Core skill rows now read "learned" / "not learned"; **Include [other]**
  applies to both learn-all and unlearn-all.
- Command-surface test covers the new commands; the interaction suite covers
  unlearn-one, unlearn-all and undo.

## v0.177

Interface rebuilt on a documented design system, plus a round of fixes.

- New visual language: graphite surfaces, one amber accent, a single type
  scale, compact page headers, consistent card padding, dark list wells and a
  real status bar. The target switch is a segmented control, and the sidebar
  marks the active screen.
- Research probes and diagnostics (kill, EXP, catalog, time-skip dumps) now
  sit behind dev mode (`DD2BRIDGE_DEV=1` or `dev_mode.txt`) instead of on the
  main screens.
- Startup no longer blocks on the filesystem: game discovery and the save
  folder scan run on a worker thread, so the window paints immediately.
- Closing the window cancels pending timers; Tk no longer prints
  "invalid command name" on exit.
- Restored window geometry is clamped to the visible screen, so a window
  saved on a disconnected monitor cannot open off-screen.
- A blocked or locked Steam account folder no longer hides the other
  accounts' saves during discovery. A failed save copy no longer leaves a
  half-written backup behind.
- Item Giver: O(1) item-ID validation instead of rebuilding a set per click,
  a recent-items list, and a clear offline message when no cached list exists.
- Item Editor: search matches names and IDs, is debounced, and fills the list
  in one bulk update. Fixed a cross-thread widget update in the element error
  path.
- Duplicate Items: debounced search and bulk list fill.
- Lists use a small canvas scrollbar instead of CustomTkinter's scrollbar,
  which flushed every pending redraw on each draw. Profiled tab builds dropped
  from seconds to a few hundred milliseconds.
- Mods: grouped into Jump, Movement, Fast travel, Respawn and Boss tools, with
  switches instead of checkboxes and short inline hints.
- Tests: the UI smoke test now runs wherever Tk can open a window (Windows
  included) and skips on headless runners. Added widget regression tests for
  the compact header, list empty state and scrollbar behaviour.
- Docs: this changelog moved out of the README; the README is now a short
  overview, with design notes under `docs/`.

```
pip install -r requirements.txt

```

Double-click `build.bat` — installs PyInstaller via pip and builds

## Protocol

- `ddbridge.lua` (REFramework, in-game) polls ~10x/sec. `ping` returns
  `pong ddbridge 1.89.1 boot={token}`, where the token is unique to that
  game process.
- Client writes `{id}|{command}|{arg}|...|B:{token}|END` to `cmd.txt`
  (atomic tmp+replace, one in-flight command at a time). Commands carrying a
  stale or missing token are rejected with `STALE_SESSION` without being
  executed; the client re-pings and retries once.
- The game writes `{id}|OK|{payload}|END` or `{id}|ERR|{msg}|END` to
  `resp.txt`, temp+rename where possible. The `|END` sentinel makes a
  truncated read detectable, so a partial payload is never treated as a
  successful result.
- Bulk data (item lists, dumps) travels through sidecar files in the same dir.
- Settings and logs: `%LOCALAPPDATA%\ArisensToolbox` (`logs\client.log`).
  Set `ARISENS_CONFIG_DIR` to override the folder for a portable install.
